# DM — учебный магазин предметов Deadlock

Сайт на HTML + CSS + JavaScript и серверная часть на **Node.js (Express) + MySQL**.
Теперь аккаунты, баланс, корзина, избранное и заявки хранятся в базе данных, а не в браузере.

## Структура проекта

```
server.js          сервер: API и раздача файлов сайта
db.js              подключение к MySQL + автосоздание таблиц
import-items.js    загрузка предметов из Deadlock API в таблицу items
sql/schema.sql     схема базы (таблицы и связи)
public/            сам сайт: index.html, style.css, script.js, images.jpg
.env               логин/пароль базы и настройки (не публиковать!)
package.json       зависимости и команды запуска
```

## Запуск

Нужен Node.js 18 или новее.

```bash
npm install
npm start
```

Сайт откроется на http://localhost:3000

При первом запуске сервер сам:
1. создаёт таблицы из `sql/schema.sql`, если их ещё нет;
2. создаёт демо-аккаунты, если таблица `users` пустая;
3. загружает предметы из Deadlock API в таблицу `items` (если она пустая).

## Импорт предметов вручную

```bash
npm run import-items
```

Скрипт берёт предметы из `https://api.deadlock-api.com`, оставляет только те, что продаются
в магазине, переводит названия категорий (spirit/weapon/vitality → Спирит/Ган/Живучесть)
и сохраняет в таблицу `items`. Повторный запуск обновляет цены и описания.

## API сервера

| Метод | Адрес | Что делает |
|---|---|---|
| POST | `/api/register` | регистрация, сразу создаёт сессию |
| POST | `/api/login` | вход по email и паролю |
| POST | `/api/logout` | выход, сессия удаляется из базы |
| GET | `/api/state` | текущий пользователь, заявки, счётчики корзины и избранного |
| GET | `/api/products?category=&search=` | каталог с фильтром и поиском (SQL `LIKE`) |
| GET | `/api/favorites` | избранные предметы |
| POST | `/api/favorites/:id` | добавить/убрать из избранного |
| GET | `/api/cart` | корзина с суммами |
| POST | `/api/cart` | добавить предмет (`{itemId}`) |
| PUT | `/api/cart/:id` | изменить количество (`{delta}` или `{qty}`) |
| DELETE | `/api/cart/:id` | убрать предмет |
| POST | `/api/orders` | оформить заказ из корзины (транзакция) |
| POST | `/api/topup` | заявка на пополнение (`{amount}`) |
| GET | `/api/admin/requests` | все заявки (только админ) |
| POST | `/api/admin/requests/:id/approve` | одобрить (списание/начисление баланса) |
| POST | `/api/admin/requests/:id/reject` | отклонить |

## Как это работает

- **Сессия.** При входе сервер создаёт случайный токен, кладёт его в таблицу `sessions`
  и отправляет браузеру в cookie `dm_sid` (`HttpOnly`). В базе хранится только токен, не пароль.
- **Пароли.** `bcryptjs`: в `users.password_hash` лежит хеш, проверка через `bcrypt.compare`.
- **Корзина.** Строки `(user_id, item_id, qty)` в таблице `cart` — у каждого пользователя своя.
- **Заказ.** Транзакция: читаем корзину `FOR UPDATE`, создаём запись в `requests`,
  копируем состав в `request_items` (название и цена на момент заказа), очищаем корзину.
- **Одобрение.** Транзакция с блокировкой строки заявки: заказ списывает души, пополнение начисляет.
  Если душ не хватает — сервер возвращает ошибку, статус не меняется.
- **Избранное.** Отдельная таблица-связка `favorites` (многие ко многим).

## Если база недоступна

`npm start` выведет «Сервер не запустился: …» и подсказку проверить `.env`.
Частые причины:

- на хостинге закрыт внешний доступ к MySQL (нужно разрешить удалённые подключения
  или запускать Node на том же сервере и использовать `DB_HOST=localhost`);
- неверный пароль/имя базы;
- база не создана (тогда один раз примени `sql/schema.sql` через MySQL Workbench).
