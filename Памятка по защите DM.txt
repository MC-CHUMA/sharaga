ПАМЯТКА К ЗАЩИТЕ ПРОЕКТА DM

Эта памятка объясняет, как устроен учебный магазин DM на HTML, CSS и JavaScript. Её можно использовать для подготовки к вопросам преподавателя.


1. КОРОТКО О ПРОЕКТЕ

DM — это демонстрационный магазин предметов из игры Deadlock. В нём есть каталог, поиск, категории, корзина, избранное, профили пользователей, баланс и простая админка. Пользователь может оформить заказ или запросить пополнение баланса. Администратор видит заявки и может одобрить или отклонить их.

Сайт работает не только в браузере: у него есть серверная часть на Node.js (Express) и база данных MySQL. Каталог, профили, баланс, корзина, избранное и заявки хранятся в базе, а браузер обращается к серверу через API. То есть заказы и пополнения теперь сохраняются на сервере и видны с любого компьютера. Поддержка с языковой моделью в проект не включена.

ВАЖНО: разделы 1–12 описывают старую версию без сервера. Актуальное описание базы, сервера и изменившихся функций — в разделе 13. Раздел 13 читать обязательно.


2. ФАЙЛЫ ПРОЕКТА

index.html — структура сайта: шапка, кнопки, формы и разделы (лежит в папке public).
style.css — внешний вид: цвета, размеры, карточки, отступы и адаптация для телефона.
script.js — поведение сайта: запросы к серверу, каталог, поиск, корзина, профили и заявки.
images.jpg — изображение Bebop, которое используется как фон.
server.js — сервер на Node.js: API, регистрация, вход, корзина, заказы, админка.
db.js — подключение к MySQL и создание таблиц из sql/schema.sql.
import-items.js — загрузка предметов из Deadlock API в таблицу items.
sql/schema.sql — схема базы данных: таблицы и связи между ними.
.env — настройки: адрес сервера MySQL, имя базы, логин и пароль.

HTML подключает CSS внутри тега <link>, а JavaScript — через <script src="script.js"> в конце страницы. Скрипт находится внизу HTML, поэтому элементы страницы уже созданы к моменту запуска кода.


3. КАК УСТРОЕН HTML

В начале документа указаны язык страницы, кодировка UTF-8 и настройка ширины страницы для телефона. Тег <title> задаёт название вкладки браузера.

Основные части страницы:

<header> — верхняя панель с названием DM и навигацией.
<nav> — кнопки перехода между разделами.
<main> — основная часть сайта.
<section> — отдельный раздел: магазин, избранное, корзина, профиль или админка.

У каждой кнопки навигации есть, например, onclick="showPage('cart')". Это значит, что при нажатии браузер вызывает JavaScript-функцию showPage и передаёт ей название нужного раздела.

Атрибут id даёт элементу уникальное имя. Например, id="cart-count" — место, в котором показывается количество товаров в корзине. JavaScript находит этот элемент по id.

Атрибут class задаёт класс. Класс можно назначать нескольким элементам. CSS использует классы для внешнего вида, а JavaScript может использовать их, чтобы показать или скрыть раздел.


4. КАК УСТРОЕН CSS

CSS записывается так:

.logo {
  color: white;
}

Сначала идёт селектор, который выбирает элемент. В фигурных скобках находятся свойства и их значения. В примере селектор .logo выбирает все элементы с классом logo, а color задаёт цвет текста.

Точка перед именем выбирает класс: .card.
Решётка выбирает id: #cart-count.
Имя тега выбирает все элементы этого типа: body, button, input.

В проекте важны такие правила:

.top оформляет шапку. position: sticky оставляет её у верхнего края во время прокрутки.
.cards использует CSS Grid. grid-template-columns: repeat(3, 1fr) делит место на три одинаковых столбца.
.menu и .card-bottom используют Flexbox. Он помогает расположить элементы в строку и выровнять их.
.hide задаёт display: none, то есть скрывает элемент.
.photo задаёт область изображения товара. position: relative позволяет разместить сердечко поверх картинки.
.heart использует position: absolute, чтобы закрепить сердечко в правом верхнем углу карточки.
z-index задаёт порядок слоёв: у сердечка он выше, чтобы кнопку можно было нажать поверх изображения.

Правило :hover срабатывает, когда указатель мыши находится над элементом. Например, кнопка меняет цвет при наведении.

Правила @media применяются при определённой ширине экрана. Здесь на узком экране карточки перестраиваются в два столбца, а на совсем маленьком — в один. Это называется адаптивной вёрсткой.

Единицы измерения:

px — пиксели, фиксированный размер.
% — доля размера родительского элемента.
vh — доля высоты окна браузера.
min() и clamp() помогают подобрать размер, который меняется в зависимости от ширины экрана.

background задаёт фон. В нём можно указать цвет, картинку, позицию и размер. padding — внутренний отступ, margin — внешний отступ, border — рамка.

Для пасхалки используются opacity, transform и transition. Они делают появление текста и исчезновение интерфейса плавными. @keyframes описывает шаги анимации.


5. ОСНОВНЫЕ ДАННЫЕ В JAVASCRIPT

В начале script.js объявлены переменные:

products — список предметов, который позже загрузится из API.
users — профили пользователей и администратора.
requests — заявки на покупку и пополнение.
cart — товары и их количество в корзине.
email — email пользователя, вошедшего в этой вкладке.
clicks — количество нажатий на Dispel Magic для пасхалки.

Переменная объявляется через let или const. let используют, когда значение может измениться. const используют, когда переменную не планируют переназначать.

Объекты записывают данные в виде пар «ключ: значение». Например, у профиля есть name, email, password, role, balance и favorites. Массив — это список значений, например список пользователей или избранных товаров.


6. ЧТО ДЕЛАЕТ КАЖДАЯ ФУНКЦИЯ

ВНИМАНИЕ: ниже описана старая версия без сервера. После подключения базы данных часть функций заменилась запросами к API — актуальный список смотри в разделе 13.4.

save() — сохраняет профили, заявки и корзину в localStorage, а email вошедшего пользователя — в sessionStorage.

user() — ищет и возвращает профиль, email которого совпадает с текущим.

money(value) — форматирует число и добавляет к нему название валюты «Душ».

safe(text) — превращает текст в безопасный HTML-текст. Это нужно, чтобы название товара с символами вроде < или > не стало HTML-разметкой.

message(text) — показывает короткое уведомление. Через три секунды оно скрывается.

showPage(name) — скрывает все разделы, показывает выбранный и обновляет содержимое нужной страницы. Например, для корзины вызывает renderCart().

Обработчик события storage обновляет данные, когда они изменились в другой вкладке того же браузера.

renderProducts() — проверяет поисковую строку и выбранную категорию, затем выводит подходящие карточки.

card(item) — собирает HTML-код одной карточки: картинку, название, описание, цену, сердечко и кнопку корзины.

itemClick(id) — проверяет, что нажали на Dispel Magic, и считает нажатия. После пятнадцатого добавляет класc egg к body, чтобы включить пасхалку.

updateHeader() — пересчитывает количество товаров в корзине и избранном, обновляет счётчики и показывает кнопку админки только администратору.

add(id) — добавляет один товар в корзину. Если пользователь не вошёл, показывает уведомление.

favorite(id) — добавляет товар в избранное или удаляет его, если он там уже есть.

renderFavorites() — показывает карточки товаров, которые сохранены в избранном.

renderCart() — показывает товары, их количество, стоимость каждой строки и общую сумму.

change(id, number) — увеличивает или уменьшает количество товара. Если количество стало нулевым, удаляет товар из корзины.

order() — считает сумму корзины и создаёт заявку со статусом pending. После этого очищает корзину.

renderProfile() — показывает форму входа, форму профиля, баланс и заявки текущего пользователя.

registerForm() — показывает поля для создания нового профиля.

login(event) — получает значения формы, ищет профиль с таким email и паролем и выполняет вход.

register(event) — проверяет, что email ещё не занят, создаёт профиль с ролью user и нулевым балансом.

logout() — очищает текущий вход и показывает форму входа.

topup() — просит ввести сумму и создаёт заявку на пополнение баланса.

status(value) — переводит статус заявки на русский: ожидание, одобрено или отклонено.

renderAdmin() — показывает заявки администратору и кнопки одобрения или отклонения.

approve(id) — меняет статус заявки. Для заказа списывает деньги с баланса; для пополнения добавляет их.

reject(id) — меняет статус заявки на «отклонено».

clean(text) — разбирает описание из API и удаляет лишние SVG-иконки и HTML-теги.

description(item, category) — берёт русское описание предмета. Если его нет, пробует использовать названия характеристик.

loadItems() — загружает данные предметов на английском и русском языках, исключает предметы за 9999 душ и вызывает отрисовку каталога.


7. ЧАСТО ИСПОЛЬЗУЕМЫЙ СИНТАКСИС JAVASCRIPT

function name() { ... } — объявление функции. Код внутри выполняется, когда функцию вызывают.

if (...) { ... } — условие. Код выполняется, если условие верно.

=== — сравнивает значения. Например, item.role === 'admin' проверяет, является ли роль администратора.

= — присваивает значение. Например, clicks = 0.

! — логическое «не». Например, !user() означает, что пользователь не вошёл.

&& — «и», оба условия должны быть верны.
|| — «или», достаточно одного верного условия.

return завершает функцию и может вернуть результат.

Массив.find() ищет один элемент. filter() оставляет элементы, которые подходят условию. map() преобразует каждый элемент. forEach() выполняет действие для каждого элемента.

document.querySelector('#cart') находит первый HTML-элемент с таким id.
document.querySelectorAll('.page') находит все элементы с классом page.
textContent меняет обычный текст элемента.
innerHTML вставляет внутрь элемента HTML-разметку.
classList.add() добавляет класс, remove() убирает, toggle() переключает.
addEventListener() запускает функцию при событии, например при нажатии или изменении поля.

onclick — обработчик нажатия, заданный прямо в HTML.
oninput — срабатывает, когда меняется текст в поле поиска.
onchange — срабатывает, когда выбирают другую категорию.
onsubmit — срабатывает при отправке формы.

JSON.stringify() превращает объект в строку для сохранения. JSON.parse() превращает сохранённую строку обратно в объект или массив.

fetch() отправляет запрос к API. async и await позволяют дождаться ответа и затем обработать данные. try/catch используется для обработки ошибки, например когда API или интернет недоступны.


8. КАК ХРАНЯТСЯ ДАННЫЕ (АКТУАЛЬНАЯ ВЕРСИЯ)

Данные теперь хранятся в базе MySQL на сервере. Браузер ничего важного не хранит: он только отправляет запросы и показывает ответ.

Таблицы базы:

users — пользователи: id, name, email, password_hash, role (user или admin), balance.
sessions — активные входы: случайный токен, user_id, время окончания.
items — предметы магазина: id, name, category, price, image, description.
favorites — избранное: пары user_id + item_id.
cart — корзина: user_id, item_id, qty (количество).
requests — заявки: тип order или topup, сумма, статус pending/approved/rejected.
request_items — состав заказа: название и цена на момент покупки.

Связи обеспечиваются внешними ключами (FOREIGN KEY): если удалить пользователя, его сессии, корзина и заявки удалятся автоматически (ON DELETE CASCADE).

Как устроен вход:

1. Пользователь вводит email и пароль, сервер ищет запись по email.
2. Пароль сравнивается с хешем через bcrypt.compare — сам пароль в базе не хранится.
3. При успехе сервер создаёт случайный токен, записывает его в sessions и отправляет браузеру в cookie dm_sid с флагом HttpOnly (его нельзя прочитать из JavaScript).
4. В каждом запросе сервер читает cookie, находит сессию в базе и понимает, кто это.

localStorage и sessionStorage в этой версии больше не используются. Они были в старой версии, где не было сервера.


9. ПРИМЕРЫ СЦЕНАРИЕВ

Добавление в корзину:
1. Пользователь нажимает кнопку «В корзину».
2. Вызывается add(id), где id — номер предмета.
3. Браузер отправляет POST /api/cart, сервер проверяет вход и записывает количество в таблицу cart.
4. Сервер возвращает новую корзину, updateHeader() меняет число рядом с корзиной.

Оформление заказа:
1. order() отправляет POST /api/orders.
2. Сервер в транзакции считает сумму корзины и создаёт заявку со статусом pending.
3. Состав заказа копируется в request_items, корзина очищается.
4. Администратор открывает админку и нажимает «Одобрить» или «Отклонить».
5. При одобрении сумма списывается с баланса пользователя в таблице users.

Пополнение баланса:
1. Пользователь вводит сумму в topup().
2. Создаётся заявка на пополнение.
3. Администратор одобряет её.
4. Сумма прибавляется к балансу пользователя.


10. ВОПРОСЫ ПРЕПОДАВАТЕЛЯ И КОРОТКИЕ ОТВЕТЫ

Почему разделы переключаются без новой страницы?
Потому что все разделы находятся в одном HTML-документе. JavaScript скрывает ненужные и показывает выбранный.

Что такое API?
Это способ получить данные из другой программы. Здесь сайт запрашивает у Deadlock API предметы и их описания.

Зачем нужны fetch, async и await?
fetch отправляет запрос. Ответ приходит не сразу, поэтому await ждёт его, а async отмечает функцию, в которой используется ожидание.

Почему данные хранятся в базе, а не в localStorage?
Чтобы они были общими для всех устройств и не пропадали при очистке браузера. Браузерные хранилища годятся только для демонстрации без сервера.

Это настоящая авторизация?
Да, для учебного проекта: пароль проверяется на сервере и хранится в виде bcrypt-хеша, а вход подтверждается случайным токеном в таблице sessions и cookie с флагом HttpOnly. Пользователь не может подделать роль или баланс через инструменты разработчика.

Можно ли реально купить предмет?
Нет. Это демонстрационный сайт: он не связан с аккаунтом Steam, не принимает оплату и не отправляет предметы в игру.

Что будет, если Deadlock API недоступен?
Предметы уже сохранены в таблице items базы данных, поэтому каталог продолжит работать. API нужен только для обновления списка и цен командой npm run import-items.

Почему используются и Grid, и Flexbox?
Grid удобен для сетки карточек, а Flexbox — для выравнивания элементов в одной строке, например кнопок шапки и цены с кнопкой.


11. КОРОТКОЕ ВЫСТУПЛЕНИЕ

«Я сделал учебный магазин предметов Deadlock. HTML задаёт разделы и кнопки, CSS отвечает за оформление, JavaScript на клиенте показывает каталог, корзину, избранное, профиль и админку. Серверная часть написана на Node.js с Express, данные хранятся в MySQL: пользователи, сессии, предметы, корзина, избранное и заявки. Пароли хранятся в виде bcrypt-хешей, вход подтверждается токеном сессии в cookie. Предметы загружаются из Deadlock API скриптом импорта. Заказ оформляется транзакцией, поэтому баланс и заявка меняются вместе».


12. ЧТО ВАЖНО НЕ ПУТАТЬ

HTML — структура страницы.
CSS — внешний вид страницы.
JavaScript — поведение страницы.
Функция — блок кода, который выполняет отдельную задачу.
Переменная — место, где временно хранят значение.
Массив — список значений.
Объект — набор связанных значений с именами.
Класс CSS — общее имя для оформления элементов.
id — уникальное имя HTML-элемента.
API — источник данных из другой программы.
localStorage — хранилище браузера, данные остаются после закрытия вкладки.
sessionStorage — хранилище текущей вкладки.


13. ВЕРСИЯ С БАЗОЙ ДАННЫХ (АКТУАЛЬНО)

13.1. Как теперь устроен сайт

Браузер (HTML/CSS/JS)  ->  сервер Node.js + Express  ->  база MySQL.

Браузер больше не хранит данные. Он отправляет запросы на адреса вида /api/products и /api/cart и рисует то, что вернул сервер. Сервер проверяет права, делает SQL-запросы и возвращает JSON.

13.2. Файлы серверной части

server.js — все маршруты API, проверка сессии, транзакции заказа и одобрения.
db.js — пул подключений mysql2 и функция ensureSchema(), которая при первом запуске создаёт таблицы из sql/schema.sql.
import-items.js — берёт предметы из Deadlock API и сохраняет их в таблицу items (INSERT ... ON DUPLICATE KEY UPDATE).
sql/schema.sql — CREATE TABLE для всех таблиц, внешние ключи и индексы.
.env — параметры подключения к MySQL и порт сервера.
package.json — зависимости: express, mysql2, bcryptjs, dotenv; команды npm start и npm run import-items.

13.3. Основные маршруты API

POST /api/register — регистрация (email проверяется, пароль хешируется).
POST /api/login — вход: поиск по email + bcrypt.compare, создание сессии.
POST /api/logout — удаление сессии из базы и очистка cookie.
GET  /api/state — кто вошёл, его заявки, количество товаров в корзине и избранном.
GET  /api/products — каталог, фильтр по категории и поиск через SQL LIKE.
GET/POST /api/favorites — список и переключение избранного.
GET/POST/PUT/DELETE /api/cart — корзина и количество товаров.
POST /api/orders — оформить заказ (транзакция).
POST /api/topup — заявка на пополнение баланса.
GET  /api/admin/requests — все заявки, только для роли admin.
POST /api/admin/requests/:id/approve и /reject — решение администратора.

13.6. Как оформляется заказ (главное для защиты)

1. Сервер открывает соединение и начинает транзакцию.
2. Читает корзину пользователя с блокировкой строк: SELECT ... FOR UPDATE.
3. Считает итоговую сумму на сервере, а не на клиенте — подделать цену нельзя.
4. Вставляет заявку в requests и её состав в request_items.
5. Удаляет товары из cart и делает COMMIT.
Если на любом шаге ошибка — ROLLBACK, и база остаётся в прежнем состоянии.

При одобрении заказа тоже используется транзакция: строка заявки блокируется, проверяется баланс, списываются души, статус меняется на approved. Если душ не хватает, сервер возвращает ошибку и ничего не меняет. Два администратора не смогут одобрить одну заявку дважды — второй увидит «Заявка уже обработана».

13.7. Безопасность

SQL-инъекции: все значения передаются через плейсхолдеры ? (prepared statements), строки не склеиваются.
XSS: текст на страницу выводится через safe(), который экранирует HTML.
Пароли: bcrypt-хеш, соль создаётся автоматически, сравнение через bcrypt.compare.
Сессия: случайный токен из crypto.randomBytes(32), хранится в базе, cookie с HttpOnly и SameSite=Lax.
Права: админские маршруты проверяют роль на сервере, а не в браузере.
Цены и баланс: считаются и меняются только на сервере.

13.8. Вероятные вопросы

Зачем нужна транзакция? Чтобы несколько изменений выполнились как одно целое: либо всё, либо ничего.
Что такое внешний ключ? Правило базы, которое не даёт создать корзину для несуществующего пользователя и удаляет связанные строки вместе с пользователем.
Почему предметы хранятся в базе, а не загружаются каждый раз из API? Сайт работает быстрее и не зависит от доступности чужого API; обновление — одной командой.
Что такое нормализация? Разделение данных по таблицам без повторов; у нас справочник предметов отдельно, а корзина и избранное хранят только ссылки (id).
Что можно улучшить? Вынести категории в отдельную таблицу, добавить пагинацию каталога, ограничить число попыток входа, добавить HTTPS и флаг Secure для cookie.
